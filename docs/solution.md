# CampusFix

> One issue. Multiple confirmations. Smarter priority.

## 1. Problem

Students face different problems in their campus and hostels such as
Wi-Fi issues, water problems, electricity failures, cleanliness,
classroom issues, and other maintenance problems.

The same problem may be reported separately by multiple students,
creating duplicate complaints. Management may also find it difficult
to understand how many students are actually affected and which
problem should be handled first.

Students also need a clear way to track whether their reported issue
has actually been resolved.

## 2. Solution

CampusFix is a campus and hostel issue management platform.

Students can either report a new problem or confirm that they are
facing an already reported problem using "I'm facing this too".

Instead of creating multiple complaints for the same problem,
CampusFix keeps one common issue and shows the number of affected
students.

This helps management understand the real impact of an issue,
prioritize important problems, assign them to the responsible team,
and track their resolution.

## 3. Campus / Hostel Selection

When a student wants to report or explore a problem, they first
select:

- Campus
- Hostel

Campus problems may include classrooms, laboratories, library,
canteen, washrooms, parking, and other common areas.

Hostel problems may include Wi-Fi, water, electricity, cleaning,
room maintenance, and other hostel-related issues.

## 4. Community Confirmation

If an existing issue matches the student's problem, the student does
not need to create another complaint.

They can select:

"I'm facing this too"

The affected-student count increases while the system keeps one
common issue.

Example:

Wi-Fi Not Working
Hostel Block A

27 students affected

After another student confirms:

28 students affected

This helps reduce duplicate complaints and shows the actual number
of students affected by a problem.

## 5. Smart Priority

Students can describe their problem in normal language.

AI can assist in identifying:

- Category
- Severity
- Location

The system uses issue severity and the number of affected students
to help determine the priority of an issue.

For example:

- Low impact → Low priority
- Moderate impact → Medium priority
- High impact → High priority

## 6. Issue Lifecycle

Report / Confirm Issue
        ↓
Category & Priority
        ↓
Admin Review
        ↓
Assign
        ↓
In Progress
        ↓
Resolved
        ↓
Student Verification
     ↙          ↘
  Fixed       Not Fixed
    ↓             ↓
 Closed        Reopened

An issue is considered completely closed after the student verifies
that the problem has been fixed.

## 7. Impact & USP

CampusFix aims to:

- Reduce duplicate complaints
- Show the real number of affected students
- Help management prioritize important issues
- Make issue tracking easier
- Improve communication between students and management
- Verify whether an issue is actually resolved

### Unique Value Proposition

"One issue, multiple confirmations — instead of multiple duplicate
complaints."

 User Flow

## 1. Start

Student opens the CampusFix application.

        ↓

## 2. Select Problem Area

Student chooses where the problem exists:

- 🏫 Campus
- 🏠 Hostel

        ↓

## 3. Explore Existing Issues

The student sees active issues related to the selected area.

Each issue shows:

- Problem title
- Location
- Category
- Priority
- Number of students affected
- Current status

Example:

Wi-Fi Not Working
Hostel Block A
👥 27 students affected
🔴 High Priority

        ↓

## 4. Is the Problem Already Reported?

              Existing Issue?
               /          \
             YES           NO
              ↓             ↓

## 5A. Confirm Existing Issue

If the student is facing an existing problem, they select:

"I'm facing this too"

The affected-student count increases.

Example:

27 students → 28 students

No duplicate complaint is created.

              ↓

        Issue Confirmed


## 5B. Report New Issue

If the problem is not already listed, the student selects:

"Report New Problem"

The student provides:

- Problem description
- Category
- Location
- Optional photo

AI can assist in identifying the category and severity.

              ↓

        New Issue Created


## 6. Priority

The system considers:

- Number of affected students
- Issue severity

to determine the issue priority.

        ↓

## 7. Admin Review

The issue appears on the admin dashboard.

Admin can:

- View the issue
- See affected students
- Check priority
- Assign the issue
- Update status

        ↓

## 8. Issue Resolution

Status flow:

Submitted
   ↓
Assigned
   ↓
In Progress
   ↓
Resolved

        ↓

## 9. Student Verification

After the issue is marked as resolved, the student can verify it.

              Issue Fixed?
               /       \
             YES        NO
              ↓          ↓

           Closed     Reopened

        ↓

## 10. End

The issue is closed after the student confirms that the problem
has been fixed.
